# Enterprise AI for GRC

Use **Administration → AI Configuration** to select offline rules, private Ollama/vLLM, or customer-owned Azure OpenAI/Bedrock. New installations start with offline rules. Once saved, the privacy router takes precedence over legacy primary/fallback settings. Local mode is appropriate only when Fornost and the model run inside the customer's network; a hosted application does not become on-prem merely by selecting this option.

Local endpoints require `FORNOST_AI_ALLOW_PRIVATE_ENDPOINTS=true`; loopback also requires `FORNOST_AI_ALLOW_LOOPBACK=true`. vLLM uses its OpenAI-compatible `/v1` base. Azure uses `https://RESOURCE.openai.azure.com/openai/v1`, with the deployment name as model. Bedrock uses `https://bedrock-runtime.REGION.amazonaws.com/openai/v1` and a Bedrock bearer API key. `FORNOST_SETTINGS_ENCRYPTION_KEY` must be configured to store keys. Changing the provider, endpoint or model requires re-entering its key and confirming retention again.

BYOK is not a zero-retention guarantee. The configuration requires an administrator's retention attestation and reference. The customer must configure Azure modified abuse monitoring or the applicable AWS account/project retention policy. Requests use stateless chat completions with `store:false`; this flag does not override provider abuse-monitoring policy. No cloud fallback is permitted from local/offline mode. Classification restrictions, budgets and emergency stop continue to apply. Secrets are always filtered; the PII toggle controls supported pattern redaction (email, Turkish identifiers/phone, IBAN and payment-card patterns), not a guarantee that every possible personal identifier will be detected.

Evidence uploads and new versions receive a preliminary review; existing versions expose **Run AI Preliminary Review**. PDF text is extracted on the server, with a 150-page / 160,000-character limit. TXT, JSON and CSV are read as UTF-8. PNG/JPEG OCR uses self-hosted Tesseract assets and English/Turkish models, with a 20-megapixel / 10 MB limit. Original images are never sent to cloud models. Browser OCR is an unverified transcription, pinned to the file hash, and confidence is capped at 40%. Scanned PDFs without text require a readable image or text PDF. A failed AI attempt never rolls back a successful evidence upload. Human approval uses the existing independent-reviewer endpoint, which AI does not invoke.

**Insights → Security Questionnaire Copilot** accepts a question list, CSV or the first worksheet of XLSX. Choose the question column and header handling. Limits are 100 questions, 3,000 characters each, and 5 MB spreadsheets. Sources are published approved current policies, active controls and independently approved current evidence with a verifiable file and version chain. The consolidated catalog is bounded to 500 policies, 500 controls and 100 approved evidence records; larger catalogs fail explicitly. Model citations must quote selected canonical sources. An affirmative model suggestion requires policy, control and evidence corroboration. Rules-only drafts remain partial or unsupported until expert review. Edit and save each row before approving it. Export requires every row approved and sources unchanged. Changes revoke row approval; rebuilding drafts replaces edits. CSV formulas are escaped and XLSX uses literal string cells.

A vendor's **Analyze Assurance Report with AI** action accepts a PDF/image/text report, extracts opinion, period excerpts, exceptions, subprocessors and CUECs, and retains verbatim source quotations and the file hash. Missing fields stay unknown; they are not treated as clean assurance. The uploaded original report is not retained by this action; keep the original in the Evidence Library for future human verification. Model excerpts not present in the document are discarded. Conversion requires a human-entered owner and CAPA plan; finding reviewers must be independent active administrators. Controls are created as drafts. Conversion is idempotent for each analysis item/target and does not close findings or approve evidence.

These workspaces require consolidated full access. Entity-scoped and module-scoped accounts cannot access cross-organization sources. Analysis audit events contain actor, operation, provider/model, timestamp, outcome and prompt digest, without document bodies. Analysis results and RFP drafts are internal application records and remain accessible to fully authorized GRC users.

## Verification

`node --import tsx --test tests/ai-for-grc.test.ts` exercises privacy routing, audit-before-egress, secret filtering, extraction, source eligibility, revision checks, spreadsheet injection, SoD and idempotent native conversion. `scripts/ai-for-grc-qa.mjs` runs only against localhost and checks the production artifact, automatic evidence review, questionnaire editing/approval, CSV/XLSX downloads, OCR assets, vendor conversion and TR/EN light/dark responsive views. The dedicated GitHub workflow provisions disposable local D1 data. Actual customer cloud/model connectivity requires customer credentials and network access.
