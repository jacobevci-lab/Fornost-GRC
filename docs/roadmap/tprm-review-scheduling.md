# TPRM decisions schedule the next review — 29 October 2026

At main `bf70d989d6a25a2293038222b2b45e9fe0370fe5`, a supplier's assigned independent reviewer can approve a new assessment cycle, but the decision never updates `third_party_profiles.next_review`. The completed assessment can therefore leave an overdue supplier review in My Work. The existing decision dialog shows neither that date nor its contract boundary. This is a source-confirmed workflow gap; customer adoption and time saved are unmeasured.

Extend the existing approval/conditional-approval dialog with the current review date, contract end and an explicit next date. A still-valid existing date is initially retained; an overdue date needs a new choice. The chosen date must be after today and no later than contract end. Bringing a future review forward is valid; no unrequested risk-frequency policy is invented. On decision, update the canonical profile and connected core vendor date with assessment, decision event and pinned evidence in one transaction. Show retained previous/new dates, decision actor/time and rationale with the assessment, and keep history available after renewal.

Preserve assigned reviewer independence, active full-access account checks and canonical evidence selection. Bind the scheduling request to the profile revision, previous date and contract end as well as the existing assessment revision; compare decision-time sources again in the transaction. A stale source retains the draft and requires explicit adoption and reconfirmation. A lost response reloads canonical state and history; retry cannot create a second decision. Legacy API calls without the new scheduling contract remain compatible and do not gain scheduling guarantees.
