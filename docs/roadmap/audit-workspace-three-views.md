# Audit workspace: desk, guide and board

## Delivery brief — 16 November 2026

Audit operators need to work through requirements, evidence and independent review without navigating eight equally prominent tabs. The portfolio hides deletion under a collapsed disclosure. The accepted designs preserve the existing Fornost themes and add three views over the same records: Desk, Guide and Board.

The default desk keeps the requirement list and selected requirement together. The guide exposes planning, fieldwork, review and closure. The board groups requirements by actual recorded work state, without drag-to-approve. Requests and workpapers can be explicitly linked to a requirement; names or matching titles must never establish that relationship. Existing unlinked work remains available at audit level.

Visible audit actions must explain deletion dependencies before confirmation. The existing atomic deletion guard and retained administrator snapshot remain authoritative. Portfolio archiving is reversible organization, not audit closure or a retention policy; history and links remain intact. Closed audits retain existing server-side protections. No user audit will be deleted as part of validation.

Acceptance: all three views share selection, filters and real data; requests/tests operate through existing permission and independent-review gates; links reject another audit's requirements; stale/partial data never becomes a success state; drafts survive view changes; TR/EN, light/dark, keyboard and narrow layouts remain usable. Test new synthetic audit creation, editing, archive/restore, eligible deletion and blocked deletion. Preserve deep links and existing advanced register access.

Validation and release evidence will be recorded below. Rollback is the code revision; optional JSON links and portfolio metadata are additive and compatible with older records. No database column migration is required.
