# Current assessment projections

Audit readiness, Control Assurance and the Continuous Assurance dashboard now check the persisted test against the current collector and rule configuration. A recent date or stored `pass` alone cannot certify current assurance.

The read-only projection checks the current rule/source fingerprint, enabled state, run receipt, unique evidence association, response hash, collection timestamp, evidence fingerprint, control mapping, review eligibility and validity dates. Newly collected evidence also carries its rule/run IDs. Legacy receipts without configuration lineage require another test; no migration fabricates lineage. Cosmetic names and connection diagnostics do not invalidate a test. Assessment input edits, credential rotation and changes reverted to an earlier value do invalidate it through the assessment revision.

Evidence remains eligible during its expiring window until actual expiry; the dashboard can still request attention. Governed re-test recovery retains its existing stricter fresh-evidence requirement. A historical completed re-test suppresses a prior error only while its own rule, target and proof still validate. The work item remains completed in history if current validation later fails; the current unresolved-error signal reappears. This projection never changes risk decisions or historical test/work/evidence records.

A new successful run under the current configuration restores current evidence coverage. Old evidence remains visible with a localized explanation. Invalid historical evidence does not permanently block a control that now has eligible proof. Manual evidence keeps its existing approval, date and integrity policy. An audit projects only evidence linked to its scoped requirements; an unrelated legacy automation record does not affect that audit.

Each joined assessment query reads its rule, collector, run and canonical evidence together. A metadata comparison also detects an evidence change between the initial record read and the joined read. This is not a transaction spanning the entire portfolio. The existing bounded source reads and incomplete/unavailable flags remain in place. Evidence projection uses at most 80 bindings per query; duplicate run associations fail closed. Migration `0090_assessment_evidence_lookup.sql` adds the lookup index and runtime schema initialization creates it idempotently. Credentials are used internally for fingerprints and are not returned by the assessment snapshot mapper.

Audit/control explanations are available in Turkish and English. Readiness HTML and CSV exports include the reasons at the displayed evaluation timestamp. Exporting does not refresh or mutate the evaluation.

Validation includes actual `executeRule` receipts against transactional in-memory SQLite, changed/removed/duplicated metadata, source and rule edits, A–B–A, recovery, approval/expiry checks, bounded queries, unavailable sources, historical re-test signals and export stability. The Workspace Layout QA scenario uses isolated local D1 synthetic receipts plus real source-edit APIs, and checks bilingual control/audit screens, downloads, responsive layouts and both themes. Vendor HTTP is substituted in unit tests; these checks do not claim certification by an external vendor.
