# Executive evidence confidence

The executive dashboard and Global Assurance Pack now consume the same bounded evidence assessment. Evidence approval, review status, validation result, exact expiry, version-chain integrity and current automation configuration all participate. Raw automation metadata without a current assessment cannot certify evidence. Date-only validity covers its whole UTC day.

`GET /api/evidence/assurance` reads canonical evidence metadata and version counts/history in one D1 batch, then uses the existing joined automation assessment. It returns no source credentials and performs no evidence, test or workflow writes. It shares the existing full-access role boundary; scoped users cannot open shared executive reports or this endpoint. Normal schema compatibility initialization remains idempotent. No migration or fabricated historical receipts are introduced.

The response is bounded at 10,000 evidence records and 5,000 history versions. Missing sources, invalid records, truncation and unavailable automation assessment explicitly withhold certification. A complete assessment may correctly contain broken, rejected, expired or outdated evidence; those are substantive results, not unavailable sources. The loaded core record scope remains unchanged. Current server evidence metadata replaces stale evidence copies for calculation; an absent loaded evidence ID prevents export. Other core record types retain the existing loaded scope. This is not a transaction covering the entire GRC portfolio or a new audit-readiness calculation.

Dashboard and report views show the assessment timestamp and offer reassessment. They refresh on focus, visibility and every 60 seconds while visible, with a 15-second request timeout. Loading/failure clears the previous evidence result. Superseded responses cannot overwrite a newer result; unmount aborts reads. Evidence/control/composite scores are withheld until evaluation completes, while unrelated core metrics remain available. The pack button is disabled during loading, partial responses and failure, and recovers after a successful refresh.

HTML downloads use the already displayed rows and evaluation timestamp; downloading itself does not reread the source. Automated evidence exclusions are explained in English/Turkish in the dashboard and pack. Historical rows remain unchanged. Existing manual legacy-integrity policy remains: legacy proof is explicitly unverified and penalized, not falsely labeled cryptographically verified.

Validation: transactional SQLite covers actual persisted receipts, settings changes, replacement receipts, manual-chain tampering, approval/date boundaries, scope preservation, record/version bounds, malformed and unavailable sources, response validation and immutable bilingual exports. The existing current-assessment browser scenario adds the real local-D1 endpoint, both locales/themes and desktop/mobile, pack timestamp/diagnostics, network/partial-source recovery, export gating and superseded-response handling. Vendor collection remains covered separately by the production execution tests with substituted vendor HTTP.
