# Read and respond to the assigned policy — 28 October 2026

## Product decision

On main `e237f8f96878da7d815ef832e9c9e005a9beb455`, a subject reaches a policy attestation from My Work or Policy Center, but Accept/Decline opens only a note and confirmation form. The subject cannot inspect the campaign's assigned policy version there. Complete that existing journey without adding a menu or changing the palette. Adoption and time saved are unmeasured.

## Journey and bounds

Assigned subject → campaign, due date and exact issued version → read content, summary, mappings and digest → explicit accept/decline with note and confirmation → retained response and original reviewed context. A superseded assigned version remains available while the campaign is open; clearly label it and never substitute the current published version. A closed campaign, invalid content or lost access blocks submission. Preserve existing late-response behavior for overdue open campaigns.

Reviewed responses bind the complete displayed source and live account/access state at the atomic write. Retain an immutable receipt with the original snapshot alongside the canonical attestation row; this is evidence, not another queue. An identical request can recover its result after a lost response; changed reuse conflicts. Legacy callers retain their existing contract and old responses explicitly lack a reviewed snapshot. Failed reads preserve the draft and disable submission. Source changes require explicit adoption and renewed confirmation.

## Acceptance and delivery

Use subject-only detail access behind existing enterprise authorization, TR/EN, light/dark and existing responsive controls. Verify SQLite input/privacy/state/integrity checks, complete source and actor races, rollback, immutable receipt and retry behavior. Real Chromium covers My Work entry, original-version review after a new publication, accept/decline, closure, failed reads, dropped responses, keyboard/focus, accessibility and twelve locale/theme/viewport views. Run repository CI and full browser workflow against the final tree before merge, recording immutable identities in the PR. Add an additive migration and update user/admin/module documentation. Rollback retains legitimate responses and their receipts. Production deployment is outside this package.
