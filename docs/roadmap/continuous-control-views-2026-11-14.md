# Continuous controls: priority and source views

Approved scope: replace the flat Continuous Controls list with a priority work list and an optional source-grouped view. Keep the existing Fornost shell, theme tokens, navigation, permissions, canonical records and actions. The third concept (guided review) is deferred.

The administrator/reviewer must find a failed or unverifiable control, inspect its recorded run and evidence, and use the existing run/pause actions without losing context. Search and owner/status filters apply to both views; counts describe the filtered controls. Switching views retains the filters and selected control. No illustrative data is persisted.

Priority order: failed controls, controls needing verification or fresh evidence, current passing controls, paused controls. A working source connection does not establish control success. Missing sources, missing/expired evidence and collection errors remain explicit. Unknown results never become a green success. Source groups include orphaned references, with no assumed connector health or device counts.

Use inline result expansion with the existing ControlRunDetail and existing evidence navigation. No new API, schema, automatic remediation, or CAPA approval behavior. Source inspection links use the existing source workbench. Keyboard expansion, Escape return to the trigger, TR/EN, theme tokens and responsive source cards are required.

Validation: focused classification regressions; existing browser workspace journey extended for search/owner/status, view/selection persistence, orphan sources, truthful counts, TR/EN, light/dark and mobile. Existing lifecycle and release checks remain required. Compare rendered captures against the two approved visual concepts, treating mock data and existing shell differences as intentional.
