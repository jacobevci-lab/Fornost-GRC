# External stakeholder delivery

GRC owners need a bounded external assessment link, a publishable customer trust portal and traceable engineering connectors. Extend the existing exchange module rather than introduce duplicate vendor, evidence or finding records.

Acceptance: selectable 7/14/30-day vendor invitations can be copied/revoked; a guest sees only the invited supplier and scope. Submission records MFA, encryption, backup/continuity, subprocessors and privacy/location declarations, creates versioned pending EVD records in the supplier's entity, and enters native independent review without approval. Reuse, expiry, revocation, changed source and cross-supplier requests fail closed.

Trust administrators publish bilingual titles/summaries, current published POL versions and enrolled framework badges. Each restricted approved PDF has an NDA requirement; all downloads still require human access approval. Requests include business identity/reason and the applicable NDA decision. Rejection, expiring grants, revocation and downloads are audited; unpublished/stale documents cannot be retrieved. Framework enrollment is not certification.

Connectors retain authenticated, idempotent ingress, configured outbound destinations and evidence-gated CAPA verification. Add a clearly labeled deterministic simulation that previews mapping/transition effects without writing fabricated live measurements or sending messages. Validate actual CTL/KRI updates and Jira completion through the same ingestion service in an isolated fixture. Add pending NDA notices to the existing Slack/Teams delivery scheduler.

Validation: unit/integration tests for token and publication boundaries, entity inheritance, NDA changes, audit receipts, notification deduplication and provider simulation; real browser journeys for vendor upload, trust request/approval/download, TR/EN light/dark desktop/mobile, and affected connector controls. Production release uses the existing migration/runtime compatibility path and exact-revision smoke check. No customer documents, credentials or real external provider calls are needed for isolated tests.

## Operation and limitations

Vendor invitations are single use; replacing an open invitation expires it, and revocation remains visible in history. New links are displayed for copying rather than automatically emailed. The external questionnaire includes the requested scope and declarations; all resulting evidence inherits the vendor entity and awaits independent review. The submitted native TPRM assessment is the reviewer work item.

Trust documents remain restricted even when NDA acceptance is optional: every request needs a human decision. Tightening an NDA requirement revokes pending/approved requests that lack consent. Unpublishing or invalidating a source withdraws access. Approved grants last seven days and downloads are watermarked. Enrolled framework labels are explicitly not certification badges. Notifications include a generic request label, not the visitor's identity or request text.

The integration cards separate **Simulate test signal** (no provider calls or live record writes) from **Test live connection** and **Sync now**. The real Entra/Jira/ServiceNow/Slack/Teams transports require customer configuration. Isolated automated tests use synthetic signals and mocked transports, without claiming a live customer-provider connection. Jira completion still requires the existing native completion evidence and governance fields; a missing proof produces an actionable conflict and never closes CAPA.
