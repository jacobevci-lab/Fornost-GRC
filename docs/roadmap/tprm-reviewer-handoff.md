# Supplier reviewer handoff — 29 October 2026

At main `9513694a91ad50019bfe5ebd9751235a32f7cf58`, supplier reviewer assignment is set only at onboarding. Administrators can disable an account, but there is no TPRM reassignment operation. Submitted assessments, finding verification, executed contract extension recording and exit can therefore remain assigned to an unavailable reviewer. This is a source-confirmed operational gap; customer adoption and time saved are unmeasured.

Add **Change reviewer** to existing supplier detail for Admins. Show the current reviewer, active assessments/open findings and the work awaiting review, choose an active independent Admin from the directory, give a reason and confirm. Bind the decision to the inspected profile and active-work snapshot. Commit the profile assignment and retained handoff event together. Existing My Work projects current pending responsibility from that profile; completed work retains the actual deciding/verifying actor. No task copies or rewritten evidence.

The assigning Admin cannot appoint themselves. The candidate must differ from the existing reviewer, supplier creator, business/risk owners, active assessment creators/submitters and open finding owners/creators/submitters. Enforce those boundaries server-side, including commit-time changes to identities, profile and active work. A disabled old reviewer does not block a legitimate transfer. Reject closed suppliers and unchanged assignments. A source refresh preserves the selected person/note, requires explicit adoption and clears confirmation; failed reads block saving. Lost responses reload the assignment/history; retry with the old snapshot cannot duplicate the transfer.

Expose bounded, paginated handoff history to existing full-access TPRM readers, with old/new reviewer, actual assigning actor/time, reason and work counts at transfer. Empty legacy history is not reconstructed. Current decisions and their evidence remain unchanged. This is an administrative reviewer reassignment, not temporary delegation or approval. Business/risk/finding owner changes, bulk transfer, automatic reassignment, notification delivery, account administration and other modules remain separate scope. No new menu, palette, migration or task store. Rollback preserves the canonical reviewer and retained events.
