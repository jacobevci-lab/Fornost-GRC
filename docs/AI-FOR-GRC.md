# Enterprise AI for GRC

Use **Administration → AI Configuration** to select offline rules, private Ollama/vLLM, or customer-owned OpenAI/Azure OpenAI/OpenAI-compatible/Bedrock. New installations start with offline rules. Once saved, the privacy router takes precedence over legacy primary/fallback settings. Local mode is appropriate only when Fornost and the model run inside the customer's network; a hosted application does not become on-prem merely by selecting this option.

Local endpoints require `FORNOST_AI_ALLOW_PRIVATE_ENDPOINTS=true`; loopback also requires `FORNOST_AI_ALLOW_LOOPBACK=true`. vLLM uses its OpenAI-compatible `/v1` base. Azure uses `https://RESOURCE.openai.azure.com/openai/v1`, with the deployment name as model. Bedrock uses `https://bedrock-runtime.REGION.amazonaws.com/openai/v1` and a Bedrock bearer API key. `FORNOST_SETTINGS_ENCRYPTION_KEY` must be configured to store keys. Changing the provider, endpoint or model requires re-entering its key and confirming retention again.

BYOK is not a zero-retention guarantee. The configuration requires an administrator's retention attestation and reference. The customer must configure Azure modified abuse monitoring or the applicable AWS account/project retention policy. Requests use stateless chat completions with `store:false`; this flag does not override provider abuse-monitoring policy. No cloud fallback is permitted from local/offline mode. Classification restrictions, budgets and emergency stop continue to apply. Secrets are always filtered; the PII toggle controls supported pattern redaction (email, Turkish identifiers/phone, IBAN and payment-card patterns), not a guarantee that every possible personal identifier will be detected.

Evidence uploads and new versions receive a preliminary review; existing versions expose **Run AI Preliminary Review**. PDF text is extracted on the server, with a 150-page / 160,000-character limit. TXT, JSON and CSV are read as UTF-8. PNG/JPEG OCR uses self-hosted Tesseract assets and English/Turkish models, with a 20-megapixel / 10 MB limit. Original images are never sent to cloud models. Browser OCR is an unverified transcription, pinned to the file hash, and confidence is capped at 40%. Scanned PDFs without text require a readable image or text PDF. A failed AI attempt never rolls back a successful evidence upload. Human approval uses the existing independent-reviewer endpoint, which AI does not invoke.

**Insights → Security Questionnaire Copilot** accepts CSV/TSV, the first XLSX worksheet, or pasted questions/TSV. Recognized Turkish/English headers automatically map Question Code, Category and Question Text; users can correct the mapping. Codes must be unique. The bilingual sample prepares eight questions covering ISO 27001, SOC 2, privacy and AI. Limits: 100 questions, 3,000 characters each, 5 MB spreadsheets. Sources remain published independently approved current policies, active controls and independently approved current evidence with verified file/version integrity. The consolidated catalog is bounded to 500 policies, 500 controls and 100 approved evidence records; larger catalogs fail explicitly.

A **Met** answer needs policy corroboration, an implemented active control and current approved evidence linked to that control. Draft/planned controls, unrelated evidence and negative configuration language cannot establish fulfillment. This check also applies to manual edits, approval and export. A model can select exact excerpts but cannot turn arbitrary prose into an assurance claim. Rules drafts remain partial/unsupported until expert review. Short source-code buttons open the native POL/CTL/EVD records. A reviewer edits and approves each response; that does not approve underlying evidence or controls. Edits revoke review, source changes block export, and rebuilding replaces edits. Reviewed CSV/Excel exports retain question code, category, question, localized status, answer, confidence, source codes and reviewer; CSV formulas are escaped and XLSX cells are literal strings.

A vendor's **Analyze Assurance Report with AI** action accepts PDF/image/text/JSON reports or existing Evidence Library documents already linked to that vendor. Stored documents require a verified current file/version chain; unrelated document IDs are rejected and evidence classification also controls model egress. Original uploaded files are not retained by this action—store the original in the Evidence Library when needed. The report is escaped inside `<untrusted_vendor_document>` and isolated from system instructions. Instruction-like lines are excluded from deterministic extraction. Delimiters are defense in depth, not a guarantee that injection is solved.

The result separates source-backed opinion/conclusion, report period freshness, exceptions, subprocessors and CUECs. An explicit critical finding takes precedence over clean opinion wording. ISO-format coverage dates support a labeled 12-month freshness indicator; it is not a legal validity or compliance decision. Missing/ambiguous dates stay unknown. Exact model quotations are validated against the document; the model cannot invent an opinion or authorize an action.

**+ Create CAPA** on an exception and **+ Create Control** on a CUEC open prefilled review forms. Human confirmation creates a native open FND or draft CTL with its vendor link and entity mapping. Finding reviewers must be eligible independent administrators; native closure/approval gates remain unchanged. Repeated confirmation of the same analysis item returns the existing canonical code. Source/profile changes block conversion. Record, conversion receipt, entity mapping and metadata-only audit event commit together; audit failure rolls back creation. Created-code buttons open the resulting record and survive reload.

These workspaces require consolidated full access. Entity-scoped and module-scoped accounts cannot access cross-organization sources. Analysis audit events contain actor, operation, provider/model, timestamp, outcome and prompt digest, without document bodies. Analysis results and RFP drafts are internal application records and remain accessible to fully authorized GRC users.

## Verification

`node --import tsx --test tests/ai-for-grc.test.ts` exercises privacy routing, audit-before-egress, secret filtering, extraction, source eligibility, revision checks, spreadsheet injection, SoD and idempotent native conversion. `scripts/ai-for-grc-qa.mjs` runs only against localhost and checks the production artifact, automatic evidence review, questionnaire editing/approval, CSV/XLSX downloads, OCR assets, vendor conversion and TR/EN light/dark responsive views. The dedicated GitHub workflow provisions disposable local D1 data. `scripts/rfp-vendor-qa.mjs` additionally covers TSV mapping, supported/unsupported response review and CSV export, sample questions, source navigation, stored vendor reports, native FND/CTL conversion and TR/EN themed mobile layouts. Actual customer cloud/model connectivity requires customer credentials and network access.
